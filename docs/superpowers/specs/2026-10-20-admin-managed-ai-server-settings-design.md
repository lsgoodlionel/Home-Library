# 管理员前端管理 AI 服务器配置设计

## 1. 背景与目标

Home Library 当前把 AI 配置拆成两层：登录账号可以在系统设置页保存 Ollama 地址和默认模型，但 AI 总开关、可信 Ollama Origin、Cloudflare Access Service Token、TLS 验证和超时仍由 Docker 环境变量控制。页面因此可能显示已经填写远程地址，后端却仍因 `OLLAMA_ENABLED=false` 或缺少 Access 凭据拒绝连接。

本次升级让管理员在“系统设置 → AI 模型配置”内完成服务器 AI 配置和账号 AI 偏好配置。服务器配置保存后立即成为后端有效配置，不修改宿主机 `.env`，不执行 Docker 命令，也不要求重启容器。非管理员继续只能使用 AI 业务功能，不能读取或修改服务器配置。

成功标准：

- 管理员可从页面启停服务器 AI、设置默认和可信 Ollama 地址、默认模型、超时、TLS 验证及 Cloudflare Access 凭据。
- 敏感配置需要管理员密码和服务器升级专用密码二次认证。
- Access 凭据加密保存、永不回显，并且不会出现在 API、日志、审计记录或前端持久化中。
- 数据库配置优先于环境变量且立即生效；可由管理员显式删除数据库覆盖并恢复环境变量配置。
- 账号级地址和模型偏好继续兼容，服务器安全边界不能被账号配置放宽。
- AI 配置或连接失败不影响藏书、检索、借阅、统计、备份等非 AI 功能。

## 2. 配置分层与优先级

### 2.1 服务器级配置

服务器级配置全局唯一，仅管理员可修改：

| 字段 | 初始来源 | 说明 |
|---|---|---|
| `enabled` | `OLLAMA_ENABLED` | AI 总开关 |
| `default_base_url` | `OLLAMA_BASE_URL` / `DOCKER_OLLAMA_BASE_URL` | 未被账号覆盖时的默认请求地址 |
| `trusted_base_url` | `OLLAMA_TRUSTED_BASE_URL` | 唯一允许携带 Access 凭据的 HTTPS Origin |
| `default_model` | `OLLAMA_DEFAULT_MODEL` | 未被账号覆盖时的默认模型 |
| `connect_timeout_seconds` | `OLLAMA_CONNECT_TIMEOUT_SECONDS` | 建立连接超时 |
| `read_timeout_seconds` | `OLLAMA_READ_TIMEOUT_SECONDS` | 响应读取超时 |
| `verify_tls` | `OLLAMA_VERIFY_TLS` | TLS 证书验证开关 |
| Access Client ID | `OLLAMA_CF_ACCESS_CLIENT_ID` | 加密保存的服务器凭据 |
| Access Client Secret | `OLLAMA_CF_ACCESS_CLIENT_SECRET` | 加密保存的服务器凭据 |

有效值优先级固定为：

```text
数据库全局配置 > Docker/.env 环境变量 > 程序默认值
```

数据库没有全局配置记录时，系统行为与现有版本完全一致。管理员执行“恢复环境变量配置”时删除数据库覆盖记录，下一次读取立即回退到环境变量。

### 2.2 账号级偏好

现有 `UserAISetting` 继续保存服务商、账号级 Ollama 地址和账号默认模型。账号配置可以选择请求目标和模型，但不能修改：

- 服务器 AI 总开关；
- 可信 Access Origin；
- Access 凭据；
- TLS 验证；
- 连接和读取超时。

账号级 Ollama 地址只有与服务器可信 HTTPS Origin 规范化后严格同源时才允许携带 Access 请求头。本地地址、HTTP 地址、IP、`.local` 地址及其他 Origin 永远不携带 Access 凭据。

## 3. 数据模型与加密

新增全局单例表 `system_ai_settings`，只允许一条有效记录。字段包括服务器级非敏感配置、Access Client ID 密文、Access Client Secret 密文、配置版本、最后修改管理员、创建时间和修改时间。

Access 两项凭据使用认证加密保存：

- 由稳定的 `APP_SECRET_KEY` 通过带固定用途标签的 KDF 派生专用数据加密密钥；不直接把 `APP_SECRET_KEY` 当作密钥材料使用。
- 每个密文字段使用独立随机 nonce，并由 AEAD 同时保证机密性和完整性。
- 密文包含格式版本，便于未来迁移；数据库不保存派生密钥。
- `APP_SECRET_KEY` 变化导致解密失败时，系统安全失败：标记凭据不可用，不发送 Access headers，不在响应或日志中输出解密异常正文。
- Client ID 和 Secret 必须同时可用；只存在一项时整组凭据视为不可用。

API 永不返回明文、密文、nonce、可逆掩码或长度信息。状态响应只包含：

- `access_client_id_configured`
- `access_client_secret_configured`
- `credentials_usable`
- `configuration_source`：`database`、`environment` 或 `default`

## 4. 认证、授权与审计

读取和修改服务器配置的接口全部使用 `require_admin`。修改、恢复环境变量配置和清除凭据还必须在同一次请求中验证：

1. 当前登录管理员的账号密码；
2. 服务器部署时设置的升级专用密码。

管理员密码使用现有密码校验函数验证；升级专用密码使用恒定时间比较。任一认证失败时不修改任何字段，也不执行连接测试。

服务器升级专用密码继续只存在于服务器环境中，不允许从页面设置、读取或恢复。它是管理员前端修改服务器配置所需的独立第二因子。

服务器未配置升级专用密码时，页面只允许读取状态和执行不含敏感输入的健康检查，所有服务器配置写操作返回“服务器二次认证未配置”。除回环地址上的本机部署外，服务器配置页面必须通过 HTTPS 访问；后端根据受信任代理协议头和部署策略拒绝在明文远程连接中提交密码或 Access 凭据。

所有成功修改写入安全审计记录，只记录：

- 操作类型；
- 操作管理员；
- 修改时间；
- 发生变化的字段名；
- 配置版本。

审计记录不得包含账号密码、升级专用密码、Access 凭据、密文、请求头、完整 URL 查询参数或上游响应正文。失败认证只记录受限的失败类型和管理员标识，不记录提交内容。

## 5. 后端接口

新增接口：

### `GET /api/system/ai-config`

仅管理员可用。返回全局服务器配置的非敏感值、配置来源、凭据状态和当前有效运行状态。环境变量中的凭据也只返回配置状态。

### `PUT /api/system/ai-config`

仅管理员可用。请求包含完整非敏感配置、管理员密码、升级专用密码，以及可选的新 Access Client ID 和 Secret。

凭据更新语义：

- 两个凭据字段都省略或为空：保留现有凭据；
- 两项均为非空：原子覆盖现有凭据；
- 只提供一项：返回 422，不修改配置；
- `clear_access_credentials=true`：显式清除两项凭据；不能同时提交新凭据。

请求先完成认证、字段校验、URL 安全校验和加密，再开启数据库事务。任何步骤失败都整体回滚。成功后增加配置版本、失效 AI 健康缓存，并使后续请求立即读取新配置。

### `DELETE /api/system/ai-config`

仅管理员可用，必须提交两项密码和明确确认标志。删除数据库覆盖项并立即恢复环境变量或程序默认配置；同时失效健康缓存。该接口不修改宿主机 `.env`。

### `POST /api/system/ai-config/test`

仅管理员可用。使用已经持久化并成为有效状态的配置执行现有非生成健康检查。生成测试继续使用现有显式确认流程，不与保存操作绑定。

现有 `/api/ai/config` 继续管理账号偏好，现有 `/api/ai/health`、`/api/ai/models` 和各业务 AI 接口统一通过新的有效运行时解析器读取服务器配置。

## 6. 运行时解析与缓存

将当前直接读取 `Settings` 的服务器配置解析集中到独立服务。解析器返回不可变的有效运行时对象，包含服务器配置、账号覆盖和 Access 使用判定。

为避免每次模型生成重复解密凭据，可以按全局配置版本缓存已解密运行时。缓存要求：

- 进程内有界；
- 保存、清除或恢复配置后立即失效；
- 不进入日志、任务记录或异常对象；
- 进程退出后消失；
- 并发读取不能看到一半更新的配置。

多实例部署下数据库是配置事实源。每次解析至少比较配置版本；任一实例观察到新版本后重建本地缓存。保存接口不依赖跨容器进程内广播。

## 7. 校验与安全限制

- 默认和账号 Ollama 地址继续使用现有 URL 规范化与 SSRF 防护。
- 可信地址必须是没有用户信息和控制字符的 HTTPS URL，且 hostname 必须是公开格式域名；不接受 HTTP、IP、`localhost`、`host.docker.internal` 或 `.local`。
- 可信地址比较只使用规范化后的 scheme、hostname 和有效端口；路径不能扩大凭据发送范围。
- 超时必须是有限正数，并设置合理上限；保持 connect timeout 小于 read timeout，read timeout 小于 Nginx AI 超时预算。
- 默认模型必须满足现有长度和字符限制。
- `APP_SECRET_KEY` 为程序默认值、已知示例值或不足生产强度时，后端拒绝保存数据库 Access 凭据，并返回不包含密钥内容的配置错误；非敏感服务器配置仍可保存。
- 关闭 TLS 验证允许支持受控自签名环境，但必须二次认证并进行独立风险确认；状态面板持续显示高风险提示。
- 关闭 AI 总开关时不创建 Ollama 客户端，不发送任何网络请求。

## 8. 前端页面设计

系统设置页的 AI 区域拆分为三个无嵌套卡片的功能区。

### 8.1 服务器 AI 配置

仅管理员可见，包含：

- AI 总开关；
- 默认 Ollama 地址；
- Cloudflare Access 可信地址；
- 默认模型；
- 连接与读取超时；
- TLS 验证开关；
- Access Client ID 与 Secret 输入框；
- “保存服务器配置”“恢复环境变量配置”“测试连接”操作。

凭据输入框加载时永远为空，只显示“已配置/未配置”。保存成功、保存失败或关闭二次认证弹窗后，前端立即清空账号密码、升级专用密码和 Access 凭据变量，不写入 `localStorage`、Pinia 持久化或 URL。

点击保存后显示二次认证对话框。关闭 TLS 验证时，在提交前再显示一次独立风险确认。恢复环境变量配置和清除凭据使用明确命名的确认选项，不能通过空输入隐式触发。

### 8.2 当前运行状态

显示：

- 配置来源；
- 服务器 AI 启用状态；
- 实际有效地址、默认模型和超时；
- TLS 验证状态；
- 两项 Access 凭据是否完整、是否可用；
- 当前账号地址是否使用 Access；
- Ollama 版本、已安装模型数、运行模型数和最后检查时间；
- 中文错误分类及不敏感处理建议。

保存成功后清除旧健康状态，再自动执行一次非生成健康检查。检查失败不回滚已经成功保存的配置，页面同时保留失败原因和“恢复环境变量配置”入口。

### 8.3 当前账号 AI 偏好

保留现有服务商、账号 Ollama 地址和账号默认模型。页面明确标注账号设置不能控制服务器 AI 总开关、可信地址、Access 凭据、TLS 和超时。

## 9. 错误处理与事务语义

- 表单校验失败：不发送请求。
- 管理员密码或升级专用密码错误：返回稳定中文认证错误，不保存任何字段。
- 加密或数据库提交失败：事务整体回滚，旧配置继续生效。
- 新配置保存成功但健康检查失败：保留新配置并显示分类错误，不伪装成保存失败。
- Access 401/403、Tunnel 502/503/1033、TLS、DNS、连接超时、读取超时、模型不存在和响应无效继续使用稳定错误码。
- 配置记录损坏或凭据无法解密：禁用 Access 凭据并返回安全诊断，不回退到部分数据库凭据。
- AI 故障不得改变图书数据，也不得使公开 `/api/health` 失败。

## 10. 兼容与迁移

- 新数据库表通过现有轻量迁移机制创建；不修改已有 `UserAISetting` 数据。
- 首次升级后没有全局配置记录，继续读取现有环境变量，避免部署行为突变。
- 管理员第一次保存服务器配置时，以当前有效环境配置作为表单初始值并创建数据库覆盖。
- `.env` 和 Compose 变量继续保留，作为首次启动、灾难恢复和无数据库覆盖时的后备配置。
- 旧账号保存的 Ollama 地址和模型继续有效；已有 AI API 路径和业务响应保持兼容。
- `APP_SECRET_KEY` 必须稳定且达到生产强度；弱默认值继续产生运维警告，并且不能用于保存数据库 Access 凭据。

## 11. 测试与验收

后端测试至少覆盖：

- 非管理员不能读取、修改、恢复或测试服务器配置；
- 两项密码缺失或错误时事务不发生变化；
- 凭据加密往返、随机 nonce、密文不等于明文、错误密钥安全失败；
- API、异常、日志和审计记录不包含密码、凭据或密文；
- 空凭据保留、成对覆盖、单项拒绝和显式清除；
- 数据库、环境变量和默认值优先级；
- 保存、清除和恢复后配置立即生效并失效健康缓存；
- 多实例版本观察和并发读取不会产生部分配置；
- 可信 Origin 与 TLS、超时、模型字段校验；
- AI 停用与连接失败不影响非 AI API。

前端测试至少覆盖：

- 服务器配置只对管理员显示；
- 配置来源、凭据状态和实际运行状态正确映射；
- 保存需要双重认证；
- TLS 关闭需要额外确认；
- 凭据不回显且敏感输入在所有结束路径清空；
- 空凭据保留、显式清除和恢复环境配置交互；
- 保存成功后触发非生成检查，检查失败不显示为保存失败；
- 稳定中文错误与账号/服务器配置边界说明。

交付门禁：

- 后端完整 `pytest`；
- 前端完整 Vitest；
- TypeScript 类型检查；
- 前端生产构建；
- 开发和生产 Compose 配置展开；
- Docker 重建及真实浏览器管理员流程；
- 无凭据、错误凭据和有效凭据三种远程连接验证；
- 敏感信息仓库和日志扫描；
- README、后端说明、API 合约、部署文档、路线图、GitHub 与 Obsidian 同步。

## 12. 非目标

- 不允许前端读取或回显已保存的 Access 明文。
- 不从应用容器修改宿主机 `.env`、Docker Compose 或 Cloudflare 策略。
- 不让普通账号修改服务器配置。
- 不在本次接入 OpenAI、Gemini、DeepSeek、Kimi、通义千问或自定义服务商的实际调用层。
- 不把服务器升级专用密码迁移到数据库或提供前端修改入口。
- 不因 AI 配置失败扩大修改藏书、检索、借阅、统计或备份业务。
